# v5.15.0 (Minor Release)

**Status**: In progress

<!-- alex-c-line-release-summary-start -->
This is a new minor release of the `@alextheman/eslint-plugin` package. It introduces new features and other backwards-compatible changes that should require little to no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Replace usage of `eslint-plugin-jsx-a11y` with `eslint-plugin-jsx-a11y-x`
  - `eslint-plugin-jsx-a11y` currently lacks ESLint v10 support, which often caused peer dependency issues when trying to use it alongside ESLint v10.
  - Given that it hasn't had a formal release in a while, I have instead decided to just swap it out for `eslint-plugin-jsx-a11y-x` which seems to be what people are instead switching to.

## Additional Notes

- I think this package is very long overdue for a major release!
- That said, the main thing blocking this from happening are the peer dependency issues - if I release a new major I would like it to properly support ESLint v10, with support for ESLint v9 dropped entirely.
- With this change, we are now very close to making this a reality - all we have left is `eslint-plugin-react`, which we can either replace like we had done with `eslint-plugin-import` and `eslint-plugin-jsx-a11y`, or wait for official support.
- At the time of writing, `eslint-plugin-react` not only last published in April 2025, but it also has a failing CI job...
- I think I most likely will replace it in a future release, but I think, before I do the major update for this package, I would like to get `@alextheman/components` v7 out first as that has a little more tech debt as of now. Once that's done, I think more work can be spent on this one.
- As a heads up, the things I am planning for this major release are:
  - Configs refactor - I like the idea of the categorisation we are currently doing, but I feel like some of the categories can be renamed to be more in-line with categorisation elsewhere, and some things can potentially be better grouped.
  - Entrypoints/directory refactor - the export space is a little cluttered as of now so I want to clean that up a bit.
  - Maybe polish up some of the rules logic - it has been some time since I last properly checked them.
- More will most likely come the more I work on the new release, but those are some ideas for now.
