# v5.16.0 (Minor Release)

**Status**: In progress

<!-- alex-c-line-release-summary-start -->
This is a new minor release of the `@alextheman/eslint-plugin` package. It introduces new features and other backwards-compatible changes that should require little to no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Migrate to using `@eslint-react/eslint-plugin` instead of `eslint-plugin-react`
  - `eslint-plugin-react` doesn't currently support ESLint v10 and is causing a bunch of peer dependency warnings when used with ESLint v10.
  - This replaces it with `@eslint-react/eslint-plugin` which seems to be better maintained and catches more errors than `eslint-plugin-react` ever did.

## Additional Notes

- This now means that this plugin is officially ESLint v10 safe - you can update to it without worrying about peer dependency issues.
- In the next major update, I would like to embrace support for ESLint v10 by changing the peer dependency range and more formally dropping support for ESLint v9.
- On top of that, the new change to `@eslint-react/eslint-plugin` also got me looking a bit into `@eslint-react/kit`, which looks to be a nice way to add custom rules for React project, which could be interesting.
- In particular, we will need it to restore the `react/jsx-props-no-spread-multi` and `react/destructuring-assignment` rules from `eslint-plugin-react`, which were previously present in the general React config. However I have decided to defer this for when we plan the next major release of this package, which may involve a larger restructure of the package anyway.
