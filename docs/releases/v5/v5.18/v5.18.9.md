**Status**: Released

This is a new patch release of the `@alextheman/eslint-plugin` package. It includes small, non-breaking changes and should require no refactoring. Please read the description of changes below.
<!-- alex-c-line-release-summary-end -->

## Description of Changes

<!-- user-editable-section-start -->
- Remove prettier rule from `internal/javascript` configuration
  - We are starting the migration to move to Oxlint/Oxfmt.
  - I am doing the Oxfmt one first, and that is expected to replace Prettier, so to help with the migration I need to remove the Prettier-specific configuration from this plugin so that rules don't clash when we run Oxfmt and ESLint together.

## Additional Notes

- I think, once the migration is complete, most of the existing configurations will be made obsolete (or moved to a new configs repository), but the plugin itself along with its plugin-specific configurations will remain.
- This plugin, along with ESLint, may still be good to keep around for the custom rules, but Oxlint seems to have better native support for a wider variety of rules that ESLint would otherwise make us install a bunch of extra plugin dependencies for.
- Oxlint and Oxfmt also seem to have better performance and feel less slow, which should lead to faster formatting/linting times both in CI and locally.
